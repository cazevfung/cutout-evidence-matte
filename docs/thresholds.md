# 判据表（随包发布）

这 12 条数值阈值 + 1 条复合规则是**冻结的标定结果**，不是可调默认值。包里的
`scripts/cutoutlib/score.py`（`DEFAULT_THRESHOLDS`）与这张表逐条一致，
`python scripts/selfcheck.py` 会在跑 demo 之前先比对一遍；任何一边改动都会当场失败。

改动阈值必须重新标定，并同时更新本表与 `score.py`，不能只为让某张图通过。

| 指标 | 阈值 | 方向 | 怎么算 | 标定依据 |
| --- | --- | --- | --- | --- |
| halo | ≤ 30.0 | 越小越好 | 合成到洋红与近白底，轮廓外 3px 环带内 `alpha·‖F−bg‖` 的均值 | 人工参照自身 27.64；本流水线钓鱼图 24.03；历史失败样本 19.41（它的脏边在轮廓内侧，本指标量的是轮廓外溢，不负责抓它 —— 它由 stray/continuity/pixel_fidelity 判死） |
| stray | ≤ 12 个连通域 | 越小越好 | 轮廓外 3px 以外的孤立 alpha 碎片：面积 ≤400px 且 alpha 总量 ≥3（贴任何底都看得见才算），数连通域个数 | 历史失败样本 21 个、人工参照 7 个、本流水线 1 个；阈值取 12 |
| hole | ≤ 0.01 | 越小越好 | 轮廓内（腐蚀 2px）同时近似洋红与近白的像素占内部面积比 | 三种样本都是 0；阈值 0.01 兜底 |
| coverage | ≥ 0.8 | 越大越好 | keep 每一项的定位区域被 alpha 覆盖的比例，取最小项 | keep 逐项定位区域被 alpha 覆盖的最小值；阈值 0.80（位置重叠口径） |
| continuity | ≥ 0.95 | 越大越好 | 竿顶→竿梢→线尾的采样路径上 alpha≥0.5 的比例（1px 容差） | 该采样路径上 alpha≥0.5 的比例；阈值 0.95 |
| pixel_fidelity | ≤ 0 | 越小越好 | alpha>0 像素与原图同坐标 RGB 的最大通道差 | 恒为 0：RGB 永远取自原图 |
| iou_ref | ≥ 0.9 | 越大越好 | 与人工参照的 IoU（参照先用 SIFT 单应映射回原图坐标） | 参照是另一机位：整场单应只能到 0.8655，按主体点位定标后 0.8962（0px），1px 容差 0.9078 |
| ref_cut | ≤ 0.02 | 越小越好 | 人工参照里 alpha>0 但被我们裁掉的比例 | 参照 alpha>0 里被裁掉的比例；0px 口径 0.063，2px 容差口径 0.018，阈值按 2px 容差判 0.02 |
| exclude_hit | ≤ 0.05 | 越小越好 | exclude 每一项定位区域被 alpha 覆盖的比例，取最大项 | 水花/UI 定位区域被 alpha 覆盖的最大比例；阈值 0.05 |
| thin_cov | ≥ 0.95 | 越大越好 | 细结构沿线的 alpha 覆盖率 | 细结构沿线 alpha 覆盖率；阈值 0.95 |
| alpha_area_frac | ≤ 0.5 | 越小越好 | 前景（alpha>0.5）像素占全图比例 —— **与提案无关**的形态检查 | 7 个实测 case 在 1.5%–15%；修好融合减法之前有一例是 **81.1%** —— 阈值 50% 卡在两者之间，把它判红 |
| alpha_evidence_ratio | ≤ 2.0 | 越小越好 | 前景面积 ÷ keep 层证据面积（P2 逐层 alpha 的并集） | 7 个实测 case 在 0.97–1.17；修好之前有一例是 6.54 —— 阈值 2.0 留一倍余量 |
| p1_leak | P1 占比 > 0.3 且 ratio > 1.5 时判红 | — | 显著性提案面积异常、并且异常部分真的漏进了结果（只是 P1 大不算错，被否决掉就没事） | 有一例 P1 占全图 42.9% 但加 P2 否决后结果正常（ratio 1.08），所以只凭「P1 大」不判红；只有 P1 占比 >30% 且真的漏进结果（ratio >1.5）才判红 |

## 归因表

指标超限时先归到一层，再动那一层；不许靠调阈值绕过。

| 指标超限 | 归因到哪一层 | 第一步动什么 |
| --- | --- | --- |
| halo | alpha | 边界去污染 / trimap 半径 |
| stray | P1/P2 | 最小面积与连通性过滤 |
| hole | alpha | 内部孔洞与低对比区 |
| coverage | P1/P2 | 提案漏了 keep 清单里的东西 |
| continuity | 几何 | 细结构没重建出来 |
| pixel_fidelity | 像素来源 | 生成图或重采样混进了结果，RGB 必须回到原图 |
| iou_ref | 整体形状 | 融合或排除区判错 |
| exclude_hit | P1/P2 | 排除区没压住 |
| alpha_area_frac | P1/P2 | 前景面积占全图过大，说明背景被当成了主体 |
| alpha_evidence_ratio | P1/P2 | 输出面积远超 keep 层证据面积 |
| p1_leak | P1/P2 | 显著性提案面积异常，且异常部分漏进了结果 |
| thin_cov | 几何 | 细结构覆盖不足 |

## uncertain 口径（三条）

**U1** 任一判据未过 → 该 case 的 `status` 必须是 `uncertain`，不许写成 pass，也不许把「看起来差不多」当判据。

**U2** 必须写明缺的是哪一层，取值只能是 `P1` / `P2` / `P3` / `几何` / `alpha` 中的一个或多个；
只写「效果不好」不算说明。

**U3** 进程仍以退出码 0 结束，但交付物里必须带 `failures`（哪条没过、数值、限值）与
`blocked_layer`；禁止静默交一张错的图。

## 参照的局限

人工参照若是另一机位拍摄，就不是原图的逐像素裁剪：整场单应无法让两者完全重合（透视与视差）。
所以 `iou_ref` 判 1px 容差口径、`ref_cut` 判 2px 容差口径；0px 严格值照样记进 scorecard，
但**严格值不作为判据**。
